# 红黑树

## 1. 什么是红黑树

{% note purple 'fas fa-wand-magic-sparkles' %}
红黑树（Red-Black Tree）是一种**自平衡二叉搜索树**。每个节点额外存储了一个 color 字段 ("RED" or "BLACK")，用于确保树在插入和删除时保持平衡。
{% endnote %}

红黑树在普通二叉搜索树的基础上，为每个节点增加一个颜色属性：

```text
红色（Red）
黑色（Black）
```

通过颜色规则限制树的高度，使查找、插入和删除操作都保持较好的效率。

```text
查找：O(log n)
插入：O(log n)
删除：O(log n)
```

红黑树不要求左右子树完全一样高，只要求树满足规定的颜色规则。

## 2. 二叉搜索树的问题

对于普通二叉搜索树中的任意节点：

```text
左子树所有节点 < 当前节点 < 右子树所有节点
```

例如：

```text
        10
       /  \
      5    15
     / \   / \
    3   7 12 18
```

普通二叉搜索树在数据有序插入时可能退化成链表：

```text
1
 \\
  2
   \\
    3
     \\
      4
```

此时查找、插入和删除的复杂度都会从 `O(log n)` 退化为 `O(n)`。

红黑树通过颜色约束和旋转操作，避免树长期退化成链表。

## 3. 红黑树的五条性质

一棵合法的红黑树必须满足以下规则。

### 1 每个节点只能是红色或黑色

```text
color(node) ∈ {RED, BLACK}
```

### 2 根节点必须是黑色

```text
root.color == BLACK
```

### 3 所有空节点都是黑色

空节点通常称为 `NIL` 节点。实际代码中一般不单独创建空节点，而是将 `nullptr` 逻辑上看作黑色节点。

### 4 红色节点不能有红色子节点

不能出现连续的红色节点：

```text
红色节点 → 红色节点
```

如果一个节点是红色，那么它的父节点和子节点都必须是黑色。

### 5 从任意节点到所有后代空节点的路径，黑色节点数量相同

从某个节点出发到所有后代 `NIL` 节点的路径上，黑色节点数量必须相同。

这个黑色节点数量称为：

```text
黑高（Black Height）
```

## 4. 为什么红黑树能够保持平衡

红黑树并不保证每条路径长度完全相同，而是通过以下规则控制树高：

1. 红色节点不能连续出现。
2. 每条路径上的黑色节点数量相同。

假设从根节点到某条路径上有 `k` 个黑色节点，那么红色节点不能连续出现，最长路径中的红色节点数量不会超过黑色节点数量。

因此最长路径不会超过最短路径的约两倍，红黑树高度满足：

```text
h <= 2log₂(n + 1)
```

所以树高为：

```text
h = O(log n)
```

这就保证了查找、插入和删除操作的时间复杂度为 `O(log n)`。

## 5. 红黑树节点结构

一个红黑树节点通常包含：

```cpp
enum Color {
    RED,
    BLACK
};

struct Node {
    int key;
    Color color;
    Node* left;
    Node* right;
    Node* parent;
};
```

节点中包含：

- `key`：节点保存的数据。
- `color`：节点颜色。
- `left`：左孩子指针。
- `right`：右孩子指针。
- `parent`：父节点指针。

## 6. 旋转操作

红黑树在插入或删除节点后，可能需要通过旋转恢复平衡。

旋转只改变树的结构，不会改变二叉搜索树的中序遍历顺序。

### 左旋

左旋示意图：

```text
      x                         y
       \
        y        ---->         / \
       / \                    x   c
      b   c                    \
                                b
```

左旋的核心过程是：

1. 让 `y` 的左子树成为 `x` 的右子树。
2. 将 `y` 放到 `x` 原来的位置。
3. 将 `x` 设置为 `y` 的左孩子。

示意代码：

```cpp
void leftRotate(Node* x) {
    Node* y = x->right;

    x->right = y->left;
    if (y->left != nullptr) {
        y->left->parent = x;
    }

    y->parent = x->parent;

    if (x->parent == nullptr) {
        root = y;
    } else if (x == x->parent->left) {
        x->parent->left = y;
    } else {
        x->parent->right = y;
    }

    y->left = x;
    x->parent = y;
}
```

### 右旋

右旋与左旋对称：

```text
        y                         x
       /                         / \
      x          ---->          a   y
     / \                           /
    a   b                         b
```

{% note purple 'fas fa-wand-magic-sparkles' %}
右旋通常用于处理左子树过深的情况，左旋通常用于处理右子树过深的情况。
{% endnote %}

## 7. 插入操作

红黑树插入通常分为两步。

### 7.1 按照普通二叉搜索树插入

首先按照二叉搜索树规则找到插入位置。

新插入的节点通常设置为红色：

```cpp
newNode.color = RED;
```

原因是：

- 插入黑色节点会改变经过该节点路径上的黑色节点数量，破坏黑高性质。
- 插入红色节点不会立即改变黑高，但可能产生红色父节点和红色子节点相连的问题。

### 7.2 修复红黑树性质

设：

```text
z：新插入节点
p：z 的父节点
g：p 的父节点，也就是祖父节点
u：p 的兄弟节点，也就是叔节点
```

常见情况如下。

#### 情况一：新节点是根节点

如果新节点直接成为根节点，将它染成黑色即可：

```cpp
z->color = BLACK;
```

#### 情况二：父节点是黑色

例如：

```text
黑色父节点
     \\
     红色子节点
```

此时没有违反红色节点规则，也不会破坏黑高，不需要修复。

#### 情况三：父节点和叔节点都是红色

示意：

```text
        黑 g
       /    \\
    红 p    红 u
    /
  红 z
```

处理方式：

```text
p 染黑
u 染黑
g 染红
```

然后继续从 `g` 向上检查。如果 `g` 是根节点，最后需要将根节点重新染成黑色。

#### 情况四：叔节点是黑色，形成直线

左左型：

```text
        黑 g
       /
    红 p
    /
  红 z
```

处理方式：

1. `p` 染黑。
2. `g` 染红。
3. 对 `g` 进行右旋。

结果类似于：

```text
       黑 p
      /    \\
    红 z   红 g
```

右右型与之对称：

```text
黑 g
   \\
   红 p
      \\
      红 z
```

处理方式是：

1. `p` 染黑。
2. `g` 染红。
3. 对 `g` 进行左旋。

#### 情况五：叔节点是黑色，形成折线

左右型：

```text
      黑 g
      /
   红 p
       \\
       红 z
```

处理方式：

1. 对 `p` 左旋，将折线变成直线。
2. 按照左左型继续处理。

右左型与之对称。

## 8. 删除操作

红黑树的删除操作比插入操作更加复杂，通常分为两步：

```text
1. 按照普通二叉搜索树的规则删除节点
2. 根据真正被移出节点的颜色修复红黑树性质
```

删除操作本身不会改变二叉搜索树的有序性，复杂之处在于删除黑色节点可能破坏黑高性质。

### 8.1 普通二叉搜索树删除

假设要删除节点 `z`。

#### 情况一：没有左孩子

如果 `z` 没有左孩子，就让 `z` 的右孩子顶替 `z` 原来的位置：

```text
删除前：

      parent
        |
        z
         \\
          R

删除后：

      parent
        |
        R
```

如果 `z` 没有右孩子，`R` 也可能是空节点。这里的核心动作不是调用某个函数，而是：

```text
把 z 的父节点指向 z 的右孩子
把右孩子的父节点设置为 z 的父节点
```

#### 情况二：没有右孩子

如果 `z` 没有右孩子，就让 `z` 的左孩子顶替 `z` 原来的位置：

```text
删除前：

      parent
        |
        z
       /
      L

删除后：

      parent
        |
        L
```

对应的核心动作是：

```text
把 z 的父节点指向 z 的左孩子
把左孩子的父节点设置为 z 的父节点
```

#### 情况三：有两个孩子

如果 `z` 同时拥有左右孩子，不能直接用某一个孩子替代它，否则可能破坏二叉搜索树的有序性。

此时应当在 `z` 的右子树中寻找最靠左的节点。这个节点就是 `z` 的中序后继，因为它是大于 `z` 的所有节点中最小的节点：

```text
          z
         / \\
        L   R
           /
          ...
         /
        y  ← 从 R 开始不断向左走，直到不能继续向左
```

寻找过程可以描述为：

```text
1. 从 z 的右孩子开始
2. 只要当前节点有左孩子，就继续向左移动
3. 到达最左侧节点后停止，该节点就是 y
```

然后进行节点移动：

```text
找到 z 的后继节点 y
        ↓
记录 y 原来的颜色
        ↓
将 y 从原来的位置取出
        ↓
将 y 放到 z 原来的位置
        ↓
将 z 的左子树接到 y 的左侧
        ↓
将 z 的右子树接到 y 的右侧
        ↓
让 y 继承 z 原来的颜色
```

需要特别注意：真正从树中移除的通常是后继节点 `y`，因此修复时记录的是 `y` 的原始颜色，而不是只记录待删除节点 `z` 的颜色：

```cpp
Color originalColor = y->color;
```

这种“把一个节点从原位置取出，再移动到目标位置”的过程，就是删除操作中节点替代的核心含义。

### 8.2 删除红色节点和黑色节点的区别

如果真正被移出的节点是红色，通常不需要修复：

```text
删除红色节点不会减少任何路径上的黑色节点数量。
```

如果真正被移出的节点是黑色，就可能导致经过该位置的路径少一个黑色节点，从而破坏黑高性质。这时可以把当前节点看作暂时承担了两个黑色，称为：

```text
双重黑色（Double Black）
```

双重黑色不是一种真正的颜色，而是删除修复过程中的临时状态。

因此删除完成后通常这样判断：

```cpp
if (originalColor == BLACK) {
    deleteFixup(x);
}
```

其中 `x` 是替代被移出节点的子树根节点。

### 8.3 删除修复中的节点角色

假设 `x` 是父节点的左孩子：

```text
        p
       / \\
      x   w
```

其中：

```text
x：当前双重黑色节点
p：x 的父节点
w：x 的兄弟节点
```

对于 `w` 的孩子：

```text
w 的左孩子：近侄子
w 的右孩子：远侄子
```

如果 `x` 是父节点的右孩子，所有情况左右对称。

### 8.4 删除修复的四种情况

下面先讨论 `x` 是左孩子的情况。

#### 情况一：兄弟节点是红色

结构如下：

```text
        p（黑）
       /      \\
   x（黑）    w（红）
```

根据红黑树性质，`p` 必须是黑色，`w` 的孩子必须是黑色。

处理步骤：

```text
1. 将 w 染成黑色
2. 将 p 染成红色
3. 对 p 左旋
4. 更新 w 为 x 的新兄弟节点
```

代码逻辑：

```cpp
if (w->color == RED) {
    w->color = BLACK;
    p->color = RED;
    leftRotate(p);
    w = p->right;
}
```

情况一通常不是最终结束条件，而是把红色兄弟转换成黑色兄弟，然后继续按照其他情况处理。

#### 情况二：兄弟节点是黑色，且两个孩子都是黑色

结构如下：

```text
        p
       / \\
      x   w（黑）
         /   \\
      黑      黑
```

兄弟节点没有红色孩子可以借用，因此：

```text
1. 将 w 染成红色
2. 将双重黑色向父节点 p 上移
```

代码逻辑：

```cpp
if (colorOf(w->left) == BLACK &&
    colorOf(w->right) == BLACK) {
    w->color = RED;
    x = p;
}
```

将 `w` 染红后，兄弟一侧少承担一个黑色，能够暂时抵消 `x` 一侧多出的黑色；但父节点 `p` 可能继续处于需要修复的状态，所以将 `x` 更新为 `p`，继续向上处理。

#### 情况三：兄弟节点是黑色，近侄子是红色，远侄子是黑色

结构如下：

```text
        p
       / \\
      x   w（黑）
         /   \\
      红近    黑远
```

处理步骤：

```text
1. 将近侄子染成黑色
2. 将兄弟 w 染成红色
3. 对 w 右旋
4. 更新 w 为新的兄弟节点
```

代码逻辑：

```cpp
if (colorOf(w->right) == BLACK &&
    colorOf(w->left) == RED) {
    w->left->color = BLACK;
    w->color = RED;
    rightRotate(w);
    w = p->right;
}
```

处理后会转换为情况四，也就是兄弟节点为黑色、远侄子为红色。

#### 情况四：兄弟节点是黑色，远侄子是红色

结构如下：

```text
        p
       / \\
      x   w（黑）
         /   \\
      黑近    红远
```

处理步骤：

```text
1. w 使用 p 原来的颜色
2. p 染成黑色
3. 远侄子染成黑色
4. 对 p 左旋
5. 消除 x 的双重黑色
```

代码逻辑：

```cpp
w->color = p->color;
p->color = BLACK;
w->right->color = BLACK;
leftRotate(p);
x = root;
```

旋转和重新染色后，`x` 所在路径缺少的黑色得到补偿，红黑树性质恢复，修复过程可以结束。

### 8.5 删除修复伪代码

当 `x` 是父节点左孩子时，修复逻辑可以写成：

```cpp
while (x != root && colorOf(x) == BLACK) {
    Node* p = x->parent;
    Node* w = p->right;

    if (colorOf(w) == RED) {
        w->color = BLACK;
        p->color = RED;
        leftRotate(p);
        w = p->right;
    }

    if (colorOf(w->left) == BLACK &&
        colorOf(w->right) == BLACK) {
        w->color = RED;
        x = p;
    } else {
        if (colorOf(w->right) == BLACK) {
            w->left->color = BLACK;
            w->color = RED;
            rightRotate(w);
            w = p->right;
        }

        w->color = p->color;
        p->color = BLACK;
        w->right->color = BLACK;
        leftRotate(p);
        x = root;
    }
}

x->color = BLACK;
```

当 `x` 是右孩子时，处理过程完全对称：

```text
左旋 ↔ 右旋
左孩子 ↔ 右孩子
```

实现时通常写成：

```cpp
if (x == x->parent->left) {
    // x 是左孩子
} else {
    // x 是右孩子，对称处理
}
```

### 8.6 为什么经常使用 NIL 哨兵节点

删除修复过程中，即使 `x` 逻辑上是空节点，也可能需要访问：

```cpp
x->parent
```

如果直接使用 `nullptr`，就无法安全访问父节点。因此经典实现会使用一个全局的黑色哨兵节点 `NIL`：

```cpp
Node* NIL;
NIL->color = BLACK;
```

所有空孩子都指向 `NIL`：

```text
没有左孩子 → left = NIL
没有右孩子 → right = NIL
```

这样即使 `x` 是逻辑上的空节点，也可以安全访问：

```cpp
x->parent
x->color
x->left
x->right
```

如果使用 `nullptr`，就需要封装颜色判断，并额外保存父节点：

```cpp
Color colorOf(Node* node) {
    return node == nullptr ? BLACK : node->color;
}
```

并且不能直接访问：

```cpp
w->left->color
```

而应该使用：

```cpp
colorOf(w->left)
```

### 8.7 删除操作整体流程

```text
找到待删除节点 z
        ↓
按照 BST 规则删除或移动后继节点
        ↓
记录真正移出节点的颜色
        ↓
移出红色节点：直接结束
        ↓
移出黑色节点：进入 deleteFixup
        ↓
根据兄弟和侄子节点的颜色分类处理
        ↓
重新染色并旋转
        ↓
恢复红黑树性质
```

删除操作的关键点是：

```text
1. 真正影响修复的是被移出节点的颜色。
2. 只有移出黑色节点时才需要修复。
3. 双重黑色是修复过程中的临时状态。
4. 左右子树的修复情况完全对称。
```

删除修复分支较多，工程实践中通常优先使用：

```cpp
std::map
std::set
std::multimap
std::multiset
```

而不是手写完整的红黑树删除逻辑。

## 9. 红黑树和 AVL 树的区别

红黑树和 AVL 树都是自平衡二叉搜索树，但平衡策略不同：

| 对比项 | 红黑树 | AVL 树 |
| --- | --- | --- |
| 平衡程度 | 相对宽松 | 更严格 |
| 查找效率 | 较好 | 通常更好 |
| 插入删除 | 调整次数通常较少 | 可能调整更多 |
| 结构变化 | 相对较少 | 可能频繁旋转 |
| 适合场景 | 插入删除较多 | 查询较多 |

可以简单理解为：

```text
AVL 树：更追求严格平衡
红黑树：允许一定不平衡，减少调整次数
```

如果数据经常插入和删除，红黑树通常更合适；如果数据基本不变但查询很多，AVL 树可能更有优势。

## 10. C++ 标准库中的应用

C++ 标准库中的以下有序容器通常使用平衡树实现，常见实现就是红黑树：

```cpp
std::map
std::set
std::multimap
std::multiset
```

例如：

```cpp
#include <iostream>
#include <map>
#include <string>
using namespace std;

int main() {
    map<int, string> users;

    users[3] = "Tom";
    users[1] = "Alice";
    users[2] = "Bob";

    for (const auto& [id, name] : users) {
        cout << id << " " << name << '\\n';
    }

    return 0;
}
```

输出：

```text
1 Alice
2 Bob
3 Tom
```

`std::map` 会自动按照键排序，常见操作的复杂度为：

```text
插入：O(log n)
查找：O(log n)
删除：O(log n)
```

如果不需要有序，只需要快速查找，可以考虑：

```cpp
std::unordered_map
std::unordered_set
```

它们通常基于哈希表实现，平均查找复杂度接近 `O(1)`。

## 11. 红黑树的核心理解

红黑树可以理解为：

```text
二叉搜索树
+ 节点颜色
+ 颜色约束
+ 旋转和重新染色
```

其中：

- 二叉搜索树保证数据有序。
- 颜色约束防止树退化。
- 旋转调整树的结构。
- 重新染色恢复红黑树性质。

最终目标是保证：

```text
树的高度始终保持 O(log n)
```

因此红黑树能够在动态数据不断变化的情况下，保持稳定的查找、插入和删除性能。

## 12. 总结

红黑树的核心规则：

```text
1. 每个节点是红色或黑色
2. 根节点是黑色
3. 空节点是黑色
4. 红色节点不能有红色子节点
5. 每条路径上的黑色节点数量相同
```

核心操作：

```text
普通 BST 插入或删除
        ↓
检查红黑树性质
        ↓
重新染色
        ↓
左旋或右旋
        ↓
恢复平衡
```

核心复杂度：

```text
查找：O(log n)
插入：O(log n)
删除：O(log n)
```

一句话概括：

> 红黑树是一种通过颜色规则、重新染色和旋转操作维持近似平衡的二叉搜索树，适合实现需要有序存储、频繁查找、插入和删除的数据结构。
